# Agentic Financial Learning & Expense Coach — Starter Project

Capstone project (Grp_Cap_17). Plain HTML/CSS/JS frontend + Python (FastAPI) backend.
No React, no mobile app — everything runs as a local website.

## Folder structure

```
capstone-financial-coach/
├── backend/
│   ├── main.py                # FastAPI app + all API routes
│   ├── database.py            # SQLite connection + schema
│   ├── models.py               # Request/response schemas
│   ├── llm_client.py           # Claude API wrapper (with offline fallback)
│   ├── requirements.txt
│   ├── .env.example            # copy to .env and add your API key
│   ├── data/                   # finance.db gets created here automatically
│   └── agents/
│       ├── orchestrator.py     # routes requests to the right agent
│       ├── expense_analyzer.py # categorizes transactions
│       ├── budget_planner.py   # budget vs. spend checks + tips
│       ├── goal_tracker.py     # savings goal progress + pacing
│       └── literacy_tutor.py   # RAG-style Q&A over a small knowledge base
└── frontend/
    ├── index.html
    ├── css/style.css
    └── js/app.js               # calls the backend API with fetch()
```

## How to run it (each teammate, locally)

### 1. Backend

```bash
cd backend
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env            # then paste your GEMINI_API_KEY inside .env
# Get a free key at https://aistudio.google.com/apikey
# (the app still runs without a key — LLM calls just return a placeholder string)

python database.py              # creates data/finance.db
uvicorn main:app --reload --port 8000
```

Backend is now live at `http://localhost:8000` — visit `http://localhost:8000/docs`
for the interactive API docs (auto-generated by FastAPI).

### 2. Frontend

No build step needed. Easiest option — use VS Code's **Live Server** extension:
right-click `frontend/index.html` → "Open with Live Server".

Or just double-click `frontend/index.html` to open it directly in a browser.

Make sure the backend is running first, since the frontend calls
`http://localhost:8000/...` for all data.
